# 상담 AI 미리보기 API 명세 초안

기준일: 2026-11-20
코드 기준: feat/ai-search의 d0f6726
상태: 기존 구현을 정리한 초안. 서비스 앱 연결과 실제 DB 검증은 진행 전이다.

## 합의한 상담 처리 순서

접수 → 진료 시작 → 상담 초안 생성·임시 저장 → AI 분석·후보와 근거 확인 → 상담 내용 저장 → 별도 완료 버튼으로 진료 완료.

상담 초안을 저장하면 실제 상담 ID를 발급하고 방문 상태는 IN_PROGRESS로 유지한다. AI 요청에는 이 상담 ID를 사용한다. 임시 저장과 진료 완료를 구분하는 서비스 변경은 구현 후 확인한다.

## 적용 대상과 현재 연결 상태

대상은 backend/ai/context_preview_routes.py의 인증 미리보기 라우터다.

- 경로: POST /api/ai/diagnosis/preview
- 로그인: 기존 hanui_session 쿠키를 서비스 인증 함수로 확인
- 요청 Content-Type: application/json
- 권한: 활성 계정인 한의사 또는 원장, 같은 한의원 소속, 해당 상담의 작성자이자 담당자
- 상담 상태: IN_PROGRESS
- 효과: 상담 접근 권한을 조회하고 검색 결과를 반환한다. 상담 내용·검색 이력·방문 상태를 저장하거나 변경하지 않는다.
- 연결 상태: 라우터 함수는 준비돼 있지만 현재 서비스 main.py에는 연결되지 않았다.

backend/context_preview_api.py의 독립 로컬 검증 앱도 같은 경로를 사용하지만, 그 앱은 symptoms만 받는다. 실제 서비스 연결에는 상담 ID가 포함된 인증 라우터를 사용한다.

## 요청

| 필드 | 형식 | 규칙 |
| --- | --- | --- |
| caseId | 양의 정수 | 서버가 발급한 실제 상담 ID. 문자열과 불리언은 허용하지 않음 |
| symptoms | 문자열 | 앞뒤 공백을 제거한 후 비어 있지 않아야 함 |

정의하지 않은 필드는 거부한다. 프런트엔드는 로그인 쿠키를 포함해 요청한다. 서로 다른 출처를 사용한다면 허용 출처와 쿠키 설정을 별도로 확인한다.

아래 ID 123은 형식 설명용이다. 실행할 때는 해당 계정이 담당하는 진료 중 상담 ID로 교체한다.

```json
{
  "caseId": 123,
  "symptoms": "기침은 전혀 없어요."
}
```

## 성공 응답

HTTP 200은 분석 요청을 처리했다는 뜻이다. 후보가 없거나 입력 확인이 필요할 때도 200일 수 있다.

| 필드 | 형식 | 의미 |
| --- | --- | --- |
| caseId | 정수 | 요청한 상담 ID |
| previewId | 문자열 | 이번 미리보기 식별자. 저장용 검색 ID와 다름 |
| symptoms | 문자열 | 분석한 입력 문장 |
| route | 문자열 | 아래 세 가지 표시 경로 중 하나 |
| message | 문자열 | 서버가 제공하는 안내 |
| total | 0 이상의 정수 | 실제 반환한 candidates 개수 |
| candidates | 객체 배열 | 서버 순서대로 반환한 병증 후보와 근거 |
| reviewMentions | 객체 배열 | 추가 확인이 필요한 표현 |
| explanationStatus | 문자열 | 현재 NOT_REQUESTED |
| historySaved | 불리언 | 현재 항상 false |

아래는 응답 형식 예시이며 실제 실행 결과나 유효한 미리보기 ID가 아니다.

```json
{
  "caseId": 123,
  "previewId": "preview-example-only",
  "symptoms": "기침은 전혀 없어요.",
  "route": "REVIEW_INPUT",
  "message": "현재 분석 범위에서 후보 검토에 사용할 증상을 확인하기 어렵습니다. 증상 표현을 확인해주세요.",
  "total": 0,
  "candidates": [],
  "reviewMentions": [],
  "explanationStatus": "NOT_REQUESTED",
  "historySaved": false
}
```

현재 candidates의 주요 값은 id, name, score, rank, keywordEvidence, semanticEvidence다. 미리보기 모델은 후보·검토 표현을 객체 배열로 받으며, schemas.py의 별도 DiseaseSearchResult·Candidate 모델과 동일한 계약으로 간주하지 않는다. 내부 근거 필드의 최종 고정과 저장 API 변환은 별도 확인한다.

## 화면 표시 규칙

| route | 표시 |
| --- | --- |
| CANDIDATE_REVIEW | 후보를 서버 순서대로 표시. 상위 3개를 먼저 보여주고 전체 보기로 나머지를 확인. 검토 표현이 있으면 함께 표시 |
| CONFIRM_INTERPRETATION | 후보 대신 message와 reviewMentions의 표현을 보여주고 증상 의미·존재 여부 확인 |
| REVIEW_INPUT | 후보 대신 message를 보여주고 입력 보완 안내 |

후보 수를 30개나 31개로 고정하지 않는다. total과 실제 반환 배열을 사용한다. RRF 점수를 확률이나 진단 정확도로 표시하지 않는다. 후보에 근거가 부족할 수 있으므로 원문 근거를 확인할 수 있게 한다.

입력 문장이나 상담 대상이 바뀌면 이전 분석 결과를 지운다. 요청 중 상담 또는 문장이 바뀐 경우 늦게 도착한 이전 응답은 표시하지 않는다. 이 동작은 서비스 화면 연결 시 구현·검증할 요구사항이다.

## 오류 처리

| HTTP 상태 | 현재 코드의 주요 조건 | 화면 처리 |
| --- | --- | --- |
| 401 | 로그인 실패·비활성 계정·분석 후 인증 재확인 실패 | 재로그인 안내 |
| 403 | 진료 권한 없음·다른 담당자 | 권한 안내 |
| 404 | 상담 없음 또는 다른 한의원 상담 | 접근 가능한 상담 재선택 안내 |
| 409 | 진료 중이 아닌 상담 | 상담 상태 확인 안내 |
| 422 | 잘못된 caseId·빈 증상·형식 불일치 | 입력 형식 확인 |
| 429 | 같은 라우터 인스턴스에서 분석 진행 중 | 잠시 후 재시도 안내. Retry-After: 1 |
| 503 | 자료 로딩·모델 실행·결과 처리 실패 | 분석 실패 안내, 이전 결과를 새 결과로 표시하지 않음 |

401의 세부 동작은 연결할 서비스 인증 함수에도 의존한다. 422 응답은 FastAPI 기본 검증 오류 배열일 수 있어 detail을 항상 문자열로 가정하지 않는다. 잠금은 라우터 인스턴스 안에서 동작하며 여러 프로세스 전체의 동시 실행 제한을 보장하지 않는다.

분석 뒤 인증과 상담 상태를 다시 확인한다. 실제 로그아웃·세션 무효화가 반영되는지는 서비스 인증 연결 후 검증한다.

## 저장 ID와 처방 추천 연결

previewId를 diseaseSearchId 또는 SEARCH_LOG의 SEARCH_UNIQN으로 사용하지 않는다. 현재 미리보기는 저장용 검색 ID를 발급하지 않는다.

병증 선택·처방 추천·검색 이력 저장을 연결하려면 서버가 발급한 실제 저장용 검색 ID와 상담·후보의 관계를 확인하는 별도 계약이 필요하다. schemas.py의 PrescriptionSearchRequest는 숫자로 구성된 diseaseSearchId와 선택 병증 ID 한 개를 요구한다. 이 요청 모델의 존재가 처방 추천 서비스 API 연결 완료를 뜻하지는 않는다.

## 다음 검증

- 최민준: 요청·응답·분기·근거 표시와 저장 ID 구분 검토. 처방 추천 연결 계약 정리.
- 이상준: 상담 초안 ID 발급, 진료 중 유지, 라우터·인증·상담 화면 연결.
- 공동: 실제 로그인·진료 중 상담 ID로 정상 입력, 부정, 불확실성, 문서 내 단어를 확인.
- 공동: 다른 담당자·다른 한의원·완료 상담·분석 중 권한 변경·입력 변경·중복 요청·모델 실패를 확인.
- 실제 DB 자료 수신 후 스키마·키·자료 건수를 대조. 가상 검사 통과와 실제 DB 통과를 구분.

가상 접근권한 검사 17건은 통과했다. 이 검사는 실제 DB·모델 호출이 각각 0건이며 실제 서비스 통합 성공을 입증하지 않는다.
