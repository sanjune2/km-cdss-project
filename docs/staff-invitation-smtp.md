# 직원 초대 이메일 설정

백엔드의 로컬 `.env`에 발신 SMTP와 직원이 접속할 프런트엔드 주소를 설정한 후 백엔드를 재시작합니다.

```dotenv
HANUI_PUBLIC_URL=https://hanui.example.com
HANUI_SMTP_HOST=smtp.example.com
HANUI_SMTP_PORT=465
HANUI_SMTP_SECURITY=ssl
HANUI_SMTP_FROM=invites@example.com
HANUI_SMTP_USER=invites@example.com
HANUI_SMTP_PASSWORD=
```

실제 접속 정보로 바꾸세요. SMTP 공급자가 STARTTLS를 사용하면 `HANUI_SMTP_SECURITY=starttls`와 해당 포트를 사용합니다. 비밀번호는 로컬 환경 변수나 비공개 설정으로 입력합니다.

`http://localhost:5173` 링크는 같은 PC에서만 열 수 있습니다. 팀 테스트에서는 수신자 PC에서 접속 가능한 프런트엔드 주소를 사용합니다.

원장이 초대를 생성하면 초대 레코드를 저장한 뒤 이메일 발송을 시도합니다. SMTP 미설정 또는 실패 시에도 화면에서 링크를 복사할 수 있습니다. 기존 유효 초대에는 재발송하지 않으므로 새 초대의 발송을 검사할 때는 최근 초대 이력이 없는 테스트 주소를 사용합니다.

가입 링크는 기존 `/staff/register` 화면과 가입 API를 사용합니다. 초대에 지정한 직무가 적용되며 가입 신청 후 원장 승인이 필요합니다. 기존 DB의 `INVITATION`과 `ACCOUNT`을 사용하며 이 변경으로 추가할 마이그레이션은 없습니다.

## 기존 수정 사항과 통합 검증 (2026-11-23)

`fix/fulltest-priority-20261123`의 `62df13d` 위에 팀 SMTP 커밋 `bba9a0f`를 통합했습니다. 기존 상담 상태 보호, 증상 문맥 처리, 처방 검색 및 용량 표시 변경은 유지됩니다. 프런트엔드는 팀 SMTP 커밋의 직원 초대 결과 표시 변경만 추가하며, 다른 화면의 메뉴·배치·스타일을 변경하지 않습니다. 팀원이 별도로 작업 중인 미공개 UI 변경은 이 브랜치에 포함되지 않습니다.

- 백엔드 79개 테스트 통과 (PostgreSQL 임시 테이블에서 초대·가입·원장 승인, 중복 초대 차단, 비원장 접근 차단, 메일 실패 시 링크 유지 포함).
- 프런트엔드 단위 테스트 5개 및 프로덕션 빌드 통과.
- 격리된 로컬 테스트 DB에서 승인받은 수신 주소로 실제 초대 1건을 생성하고 SMTP 발송 결과 `sent` 확인. 생성 API 약 0.755초, 링크 검증 HTTP 200, 중복 초대 HTTP 409.
- 실제 메일의 가입 링크는 테스트 프런트엔드 `http://localhost:5175`를 사용합니다. 다른 PC에서 열려면 수신자가 접속할 수 있는 서비스 주소가 필요합니다.
- 메일 서버 수락을 확인했으며 받은편지함 도착 여부는 확인하지 않았습니다. 실제 초대는 가입으로 소비하지 않고 유지했습니다. 가입·승인은 별도의 임시 테이블 테스트에서 검증했습니다.
- SMTP 비밀번호, 초대 토큰 및 실제 가입 URL은 Git에 포함하지 않습니다. 인스턴스 GPU 성능 측정 결과는 이 SMTP 검증에 포함되지 않습니다.
