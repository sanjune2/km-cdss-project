# 전체 기능 검사에서 발견한 우선 오류 수정

기준 브랜치 `hanui-api-v13`, 기준 커밋 `a04b7a8df44ffaa0719dcbf2af2830cd06b5804a`에서 `fix/fulltest-priority-20261123`으로 분리했다. 원본 브랜치와 main에는 합치지 않았다.

## 기능 변경

| 검사 항목 | 수정 |
|---|---|
| F01 과거 기록의 실제 처방량 누락 | Patients의 한의사·데스크 상세에서 공통 표시 함수를 사용. 원본 참고량과 실제 처방량을 구분하고 실제 단위를 보존 |
| F02 구형 상태 API의 저장 보호 우회 | 구형 대기 복귀 요청은409로 차단. 진료 시작은 현재 START 처리에 위임해 상담 ID 생성·권한·잠금을 공유 |
| F03 문맥 분류 미연결 | 현재 환자의 긍정 증상만 검색 입력으로 사용. 부정·불확실·과거·타인 언급 및 미판정 표현은 검색 근거에서 제외 |
| F04 긴 설명 대기 | 검색 사이에 후보별 잠금을 양보. 선택된 연결 처방 설명을 부모 병증의 남은 설명보다 우선 처리. 선택적으로 상주 llama.cpp 서버 사용. 같은 자료·표현의 검증된 생성/검토 응답을 메모리에 재사용 |
| F05 자연어 키워드 누락 | 분류된 긍정 등록 용어를 키워드 연결과 근거 대조에 공통 사용. 의미 검색에도 분류된 긍정 표현만 전달 |
| F06 연락처·주소 공란 | 권한과 한의원 범위를 유지하며 방문 응답에 phone/address 추가. 기존 상담 화면에 전달되는 데이터 보완 |
| F07 비밀번호 변경 후 기존 세션 유지 | 비밀번호 변경과 같은 트랜잭션에서 다른 세션 폐기. 변경을 수행한 현재 세션은 유지 |
| F08 데스크 상세 날짜 공란 | 버전의 savedAt을 작성 날짜로 표시. 기존 createdAt 호환 유지 |
| F09 작은 화면 배치 | 팀원 UI 작업과 겹치므로 이번 기능 수정에서 제외 |

DB 테이블 변경은 없다. 기존 INPUT_CONTEXT/SEARCH_TRACE/INGREDIENTS_JSON과 LOGIN_SESSION을 사용한다. 과거 검색 결과를 자동 소급 재계산하거나 원본 용량을 채워 넣지 않는다.

## 팀원 UI와 합치는 범위

CSS, App, Today, Consultation, 메뉴·배치·스타일은 변경하지 않았다. 화면 파일 변경은 Patients의 용량 표시 부분과 Prescriptions의 날짜 표현 한 줄이다. prescriptionUtils에는 과거 quantity 필드의 표시 호환을 추가했다. UI의 파일 전체를 덮어쓰지 말고 해당 표시 부분만 적용한다. 기능 수정과 UI 표시 수정은 별도 커밋으로 나눈다.

## 문맥 정책과 한계

`patient-current-affirmed-v1`은 표현 분류 정책이며 환자의 진단이나 처방 적합성 확정을 뜻하지 않는다.

- `기침이 심하지는 않아요.`는 합의한 기준대로 AFFIRMED, `기침은 전혀 없어요.`는 NEGATED, `기침인지 모르겠어요.`는 UNCERTAIN이다. 분명한 짧은 등록 표현은 결정 규칙으로 먼저 처리한다.
- 복합 문장은 로컬 Qwen 모델로 문맥·존재·경험 주체·시점을 확인한다. 현재 환자의 긍정 언급만 사용한다. 부정·불확실·과거·타인·문맥 미판정은 검색 근거가 아니다.
- 등록되지 않은 증상도 원문의 정확한 연속 범위로 확인되면 의미 검색에 사용할 수 있다. 키워드 연결이나 설명용 등록 표현으로 임의 승격하지 않는다.
- 모순된 판정은 해당 표현을 미판정으로 격리하고 reviewRequired와 메시지를 반환한다. 다른 독립된 긍정 표현은 유지한다. 실패·형식 오류·출력 잘림은 긍정으로 대체하지 않는다. 추가 표현의 원문 위치가 반복으로 모호하면 검토 대상으로 남긴다.
- API와 저장 검색에 inputAssessment를 추가한다. 기존 candidates, evidence, rankingBasis 필드는 유지한다. 설명 모델에 전달하는 증상은 검증된 등록 긍정 표현이다.
- 개발용 실제 모델7문장의 **검색 포함/제외 동작**을 확인했다. 복합 문장에서는 문맥과 존재 판정이 모순되어 미판정으로 격리된 사례가 있었다. 이는 독립 정답셋의 문맥 라벨 정확도나 임상 품질 평가 통과를 뜻하지 않는다. 신규24문장의 대상 범위·정답 검토와 교차 검토는 별도로 필요하다.

## 상주 설명 모델 설정

기존 llama-completion 방식도 지원한다. 상주 서버를 사용할 때만 아래 의존성을 설치하고 추가 환경변수를 설정한다.

```powershell
python -m pip install -r backend/requirements-local-model.txt
```

- `KM_CDSS_LLAMA_SERVER_URL`: 예시 `http://127.0.0.1:8091`. 인증정보·경로·쿼리가 없는 루프백 HTTP 주소만 허용한다.
- `KM_CDSS_LLAMA_SERVER_API_KEY`: 비공개 설정 파일에서 제공. 키 파일과 .env는 Git에 올리지 않는다.
- 기존 `KM_CDSS_LLAMA_EXECUTABLE`, `KM_CDSS_EXPLANATION_MODEL`, 모델/토크나이저 캐시는 유지한다. 서버는 같은 검증된 GGUF를 사용한다.

서버 실행 예시의 파일 경로는 각 PC의 검증된 파일로 지정한다.

```powershell
llama-server.exe --model "<검증된 GGUF 경로>" --host 127.0.0.1 --port 8091 --ctx-size 4096 --parallel 1 --no-webui --no-slots --cache-ram 128 --cors-origins http://127.0.0.1:8091 --api-key-file "<비공개 키 파일>"
```

HTTP 요청은 환경 프록시와 리디렉션을 사용하지 않으며 취소·제한시간·정상 종료를 확인한다. 캐시는128개로 제한하고 프롬프트·모델 설정/파일·입력 자료가 바뀌면 재사용하지 않는다. 원문 인용 검증에 실패한 생성과 거부된 검토는 캐시에 저장하지 않는다. 환자 자유 문장을 처리하는 문맥 요청은 캐시하지 않는다. 캐시를 사용해도 기업 원본 검사·인용 대조·검토 결과 검사를 다시 수행한다.

공식 서버 계약: https://github.com/ggml-org/llama.cpp/tree/master/tools/server

## 재검증

- 백엔드72개 테스트 통과. PostgreSQL 임시 테이블의 저장 보호, 구형 START, 세션 폐기, 연락처, 용량 버전 보존을 포함하며 건너뜀0.
- 프런트5개 테스트와 배포 빌드 통과. 코드 검사 오류0, 기존 경고18.
- 전달받은 덤프의 별도 복제 DB에서 최종 업무 흐름 HTTP233회, 추가 회귀 HTTP14회 모두 예상 응답. 반복 조회130회를 포함한다. 상태 단언11개와 추가 검사7개 모두 통과.
- 실제 브라우저에서 한의사/데스크 과거 기록의 원본9 L와 실제2.5 mL 분리 표시, 상담 연락처·주소 복원, 데스크 작성 날짜 표시를 확인했다.
- 실제 프린터 출력, 임상적 처방 적합성, 다중 사용자 부하, 새 정답셋의 독립 분류 정확도는 별도 검증 범위다.

### 설명 지연 측정

같은 PC·E5·Qwen GGUF로 측정했다. 단일 시나리오 측정이며 평균/p95/SLA가 아니다.

| 구간 | 이전 | 수정 후 |
|---|---|---|
| 연결 처방 목록 첫 응답 | 약1.456초 | 약1.921초 |
| 연결 처방 첫 설명 | 약111.04초 | 약51.62초 |
| 연결 처방 상위3개 설명 완료 | 약173.31초 | 약108.12초 |
| 부모 병증 상위3개 설명 종료 | 약81.5초 | 약160.99초 |

선택한 처방을 우선 처리하므로 부모 병증의 남은 설명은 뒤로 밀린다. 목록 응답 시간이 줄었다는 의미는 아니다. 같은 설명을 다시 요청한 별도 캐시 검사에서는 첫 응답0.157초,3개 설명 완료0.314초였고 생성·검토 캐시 적중을 DB 추적으로 확인했다. 이 중복 검사에서는 부모의 불필요한 설명을 먼저 취소했다. 최초 생성 시간과 캐시 적중 시간을 섞어 해석하지 않는다.

재현 명령은 기존 테스트와 동일하며, PostgreSQL 검사는 테스트용 설정에서 `HANUI_RUN_POSTGRES_TESTS=1`로 실행한다.

```powershell
python -m unittest discover -s backend/tests -v
```

프런트 폴더에서:

```powershell
npm ci
npm test
npm run build
```
