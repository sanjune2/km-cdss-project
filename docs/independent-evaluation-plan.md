# 독립 품질 평가 준비 계획 초안

작성일: 2026-11-20

기존 개발 문장과 분리한 새 문장으로 문맥·존재 언급 분류와 원문 근거 연결을 평가한다. 현재 단계는 준비 계획이다. 새 문장·기대 라벨·수치 통과 기준은 아직 확정하지 않았으며 모델 평가는 실행하지 않았다.

## 검토 담당과 결과 표시

최민준이 문장과 기준을 먼저 단독 검토한다. 교차 검토는 추후 진행한다.

현재 결과에는 단독 검토 기준이라는 사실을 표시한다. 여기서 독립은 기존 개발 세트 및 모델 출력과의 분리를 뜻한다. 외부 검토자나 임상 전문가의 검증을 뜻하지 않는다.

추후 교차 검토자는 모델 출력을 보기 전에 원문과 라벨 기준을 검토한다. 검토자·날짜·의견 차이와 최종 처리 이유를 남긴다.

## 1차 평가 범위

| 평가 영역 | 확인할 내용 |
| --- | --- |
| 표현 탐지 | 사람이 미리 지정한 원문 범위를 찾는지, 범위 누락·추가가 있는지 |
| 문맥 | 환자 증상·신체 부위만의 언급·비증상 문맥을 구분하는지 |
| 존재 언급 | 환자 증상 범위에서 AFFIRMED·NEGATED·UNCERTAIN·UNASSESSED를 구분하는지 |
| 입력 확인 분기 | 불확실성·입력 보완 경로와 후보 표시 규칙을 지키는지 |
| 원문 근거 연결 | 후보 ID·출처·발췌 위치·발췌문이 기업 원문과 일치하는지 |
| 자료 부족 처리 | 미평가 처방을 보존하고 점수·순위를 임의로 부여하지 않는지 |

병증·처방의 임상적 정답, 환자별 안전성, 용량 적합성은 이번 개발 평가만으로 확정하지 않는다. 정답 병증·처방을 지정하는 평가를 추가하려면 해당 내용을 검토할 수 있는 담당자와 별도 기준이 필요하다.

시점·심각도는 현재 분류기가 평가하는 범위와 구분한다. AFFIRMED를 현재 증상 존재나 경증 확정으로 바꾸어 해석하지 않는다.

## 신규 문장 구성 제안

초기 규모는 24문장을 제안한다. 각 유형 4문장씩 작성하며 최종 구성은 단독 검토 후 고정한다.

| 주 유형 | 제안 건수 |
| --- | --- |
| 증상 존재의 긍정 언급 | 4 |
| 증상 자체의 존재 부정 | 4 |
| 증상 존재의 불확실성 | 4 |
| 강도 부정 | 4 |
| 신체 부위만의 지정 범위 | 4 |
| 용어·문서·사물 등 비증상 문맥 | 4 |

여러 증상이 있는 문장과 한 증상만 부정하는 문장을 포함한다. 문장별 주 유형은 하나로 집계하되, 지정 범위가 여러 개면 각 범위의 기준을 따로 기록한다. 단순 인용 부호만으로 환자 증상 언급을 비증상으로 처리하지 않는다.

이 표는 구성 제안이며 실제 평가 문장이나 정답 라벨이 아니다.

## 기존 개발 자료와 분리

- 기존 NORM·ADD 24문장, 병증 검색 개발 대조 49건, 예제 화면과 단일 실행 문장을 새 평가 결과에 다시 포함하지 않는다.
- NORM-008과 그 설명용 비교 문장은 기존 개발·검토 사례로 유지한다.
- 기존 문장의 증상 단어만 바꾼 문장은 근접 중복으로 검토하고 분리 이유를 남긴다.
- 기대 범위와 라벨은 모델 출력을 보기 전에 작성·검토·고정한다.
- 애매한 문장은 검토 보류로 표시한다. 이를 모델용 UNASSESSED 라벨과 혼동하거나 자동 정답으로 사용하지 않는다.
- 기업 자료의 등록 표현과 검색 대상 범위에 맞는지 실행 전에 확인한다. 제외 사례가 있으면 이유와 수를 함께 남긴다.
- 실행 후 모델이 못 찾았거나 틀린 사례를 임의로 제외하지 않는다.

## 기록할 정답 기준

각 문장에는 사례 ID, 원문, 주 유형, 대상 원문 범위, 기대 문맥, 해당 범위의 기대 존재 언급, 라벨 이유, 검토자·검토일·검토 상태를 남긴다.

환자 증상이 아닌 범위의 존재 언급은 기존 정책에 맞게 처리하고, 환자 증상에 대한 존재 분류 정확도와 구분해 집계한다. 대상 범위가 누락돼도 평가 분모에서 제외하지 않는다.

## 측정값과 통과 기준

| 항목 | 집계 원칙 |
| --- | --- |
| 범위 탐지 | 기대 범위 수·일치·누락·추가 수를 모두 보고 |
| 문맥 정확도 | 미리 고정한 전체 기대 범위를 분모로 사용. 누락도 오답 처리 |
| 존재 언급 정확도 | 사람이 환자 증상으로 지정한 기대 범위를 분모로 사용. 문맥 오분류·누락도 오답 처리 |
| 문맥과 존재 언급 동시 일치 | 둘 다 맞은 범위 수와 전체 기대 범위 수를 함께 표시 |
| 유형별 결과 | 긍정·부정·불확실성·강도 부정·신체 부위·비증상별 건수와 오류 표시 |
| 근거·자료 부족 | 원문 연결 오류, 후보 누락, 미평가 처방의 임의 점수 부여 등 위반 건수 표시 |

기본 불변조건은 원문 위치·ID 연결 오류 0건, 원본 자료 변경 0건, 확인 보류 경로의 후보 노출 0건, 미평가 처방의 임의 점수·순위 부여 0건을 통과 기준 초안으로 둔다.

분류 정확도 등의 수치 목표는 문장·라벨 검토 후 첫 모델 실행 전에 확정한다. 수치 기준이 미정이거나 필수 검증이 빠진 상태에서는 전체 품질 통과로 선언하지 않는다. 작은 개발용 세트의 결과를 일반적인 임상 정확도로 확대하지 않는다.

## 실행 전 고정할 항목

평가 문장과 라벨, 검토 범위, 분모, 제외 기준, 수치 통과 기준, 코드 커밋, 모델·프롬프트 버전, 생성 옵션, 검색 설정과 자료 해시를 고정한다. 정답 라벨은 모델 입력에 포함하지 않는다.

첫 실행 결과와 오류를 그대로 보존한다. 결과를 보고 프롬프트나 규칙을 보완하면 이 세트는 이후 회귀 검사에 사용하고, 같은 세트 재실행을 새로운 독립 평가로 보고하지 않는다. 수정 모델의 새 독립 평가는 별도 문장 세트로 준비한다.

## 다음 준비 단계

1. 이 계획 초안을 확인한다.
2. 신규 문장 24개와 대상 범위·기대 라벨 초안을 작성한다.
3. 최민준이 단독 검토하고, 보류·제외 이유를 기록한다.
4. 수치 기준과 실행 버전을 확정하고 평가 자료를 고정한다.
5. 모델 평가를 실행하고 전체 분모와 유형별 결과를 기록한다.
6. 교차 검토를 추가할 때 별도 검토 이력으로 반영한다.

NORM-008의 사용자 기준 확인은 [강도 부정 기준](strength-negation-criteria.md)에 기록돼 있다. 문맥 v3 모델의 기존 UNCERTAIN 결과와의 불일치는 이 계획 문서로 해결되지 않는다.
